# 运行记忆：唯一版本源、审核发布与回滚

## 状态与数据来源

`data/memory_registry.db` 是纳管后的唯一运行记忆源。它按交易账户身份隔离保存不可变版本、候选、人工审核与发布事件。

- **读取不迁移、不写入、不恢复基准。** 尚未纳管时，兼容读取严格复现旧模型的 Markdown 优先 / JSON 备选逻辑；空 Markdown 不会意外启用 JSON 或结构化心法。
- 首次初始化复制当时实际模型输入为兼容快照。旧 `structured_trading_memory.json` 中的 enabled、健康分和样本数不代表批准；只将这些记录登记为待审核或静态阻断候选。
- 纳管后，修改旧 Markdown/JSON 不能改变模型有效记忆。新账户无已发布版本时，不读取其他账户的旧全局记忆。
- 运行记忆日期来自实际有效内容变更；版本纳管时间、最近复盘尝试和最近成功报告分别显示。NO_CHANGE 不制造新规则日期。
- 旧兼容上下文仍可原样保留，以避免迁移时改变交易行为；它单独折叠展示，不冒充已审核规则。移除也需建立 CLEAR_LEGACY 候选并明确发布。

## 正常流程

1. 在后台“自进化”页点击“纳管当前记忆（不改变输入）”，输入 `INITIALIZE MEMORY`。此操作不会启用旧4条心法。
2. 自动复盘和管理员操作都只创建候选：ADD、REVISE、DEACTIVATE。管理员还可提议 CLEAR_LEGACY。
3. 审核候选文本、适用条件和反例。ADD/REVISE 须选择至少两条不同的、当前账户中已平仓且有结算数值的证据，填写审核说明并输入 `PUBLISH MEMORY`。
4. 后端重新核对候选内容、账户、页面 revision、成交证据指纹与静态安全约束，通过后在一个 SQLite 事务中发布新版本。
5. 模型与前后台读取相同的版本内容和指纹。决策记录保存其使用的记忆版本/指纹；最终下单前发现有效记忆已变化，会要求重新决策。
6. 拒绝只改变候选状态，不修改运行内容。回滚须选择真实历史版本、查看内容、填写原因并输入 `ROLLBACK MEMORY`；回滚发布一个新版本，不改写历史，不恢复交易数据。

两个样本只是最低证据完整性要求，不代表统计显著、因果成立或收益已经验证。静态检查仅过滤已知危险模式，不能替代人工审查。记忆只是研究参考，不能修改止损、风险预算、订单保护或强制交易。

## 并发、失败与安全边界

- 发布、初始化与回滚避开在途 trader、brain 和 self-improvement 周期；不终止任务、不要求平仓。
- 候选入库与账户变化通过现有 writer 锁协调；版本与候选使用乐观 revision 检查，成交数据变化也要求刷新重审。
- 发布版本与候选正文不可原地改写；重复提交已发布候选不会再次产生发布。
- 自动复盘固定账户范围。NO_CHANGE 和重复复盘不会清空待审队列；失败仍保留上次成功报告和已发布记忆。
- 登记库异常不会回退到另一份旧文件或自动恢复黄金基准。新发布的有效文本限制为32000字，不静默截断。
- 数据库权限为0600，运行数据库与测试诊断均被 Git 忽略。

## API

- `GET /api/v1/admin/memory`：普通管理员可读，同源 publication / candidates / versions / evidence / schedule。
- `POST /api/v1/admin/memory/initialize`：超级管理员，确认纳管。
- `POST /api/v1/admin/memory/candidates`：超级管理员，创建候选，不立即生效。
- `POST /api/v1/admin/memory/candidates/{id}/publish`：超级管理员，revision、证据指纹、审核说明和确认短语。
- `POST /api/v1/admin/memory/candidates/{id}/reject`：拒绝候选并保留记录。
- `GET /api/v1/admin/memory/versions/{id}`：查看当前账户的历史版本。
- `POST /api/v1/admin/memory/versions/{id}/restore`：确认回滚内容为新版本。

旧 POST `/memory` 仅转为创建待审候选并返回 `saved:false, pending:true`。旧 toggle、按索引 DELETE、整表 PUT 和“黄金基准回滚”返回410，不能绕过新流程。旧 Python 直写辅助函数同样封闭。

## 迁移验证与发布注意事项

使用服务器只读数据的隔离副本完成验证：纳管前后实际记忆文本逐字一致、指纹一致；旧4条记录自动启用数0；候选发布会改变有效版本，回滚恢复原指纹；原 Markdown/JSON 文件不变。所有测试均未向线上发布规则、调用模型或交易接口。

首次纳管内容不变，不能因此宣称已经学习了新规则。若最近复盘是 NO_CHANGE，等待管理员审核或后续有效证据才会有规则变更。

**代码回退注意：** 一旦发布了新记忆，不应回退到不支持登记库的老镜像，因为老代码仍会读取旧 Markdown。规则回滚使用本页的版本回滚；代码回退必须先核对有效记忆读取方式和内容指纹，不能恢复旧业务数据覆盖新成交记录。
