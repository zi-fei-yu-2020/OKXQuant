# 统一交易提示词与输出契约

契约版本：`trading-evidence-v1`。单模型、投委会最终裁决、影子模型输出和后台预览共用 `scripts/trading_prompt.py`，不再各自拼一套相互矛盾的开仓要求。

## 一、实际组合流程

1. **基础系统规则**：`BASE_SYSTEM`，不可由编辑器模块禁用或替换。执行器拥有最终否决权。
2. **内置风格**：`STYLE_SYSTEM` + `STYLE_USER`，都属于程序管理的风格层。保留 1H~4H 波段、多空对称和证据审查，不规定开仓次数或目标评分。
3. **用户偏好**：当前选中方案的模块/简单策略及 `system_prompt_override.txt`。它们位于 User 消息内的 `user_preferences` 数据结构，不追加为新的 System 权限。
4. **动态输入**：账户、挂单、市场矩阵、新闻、历史记忆和逐标的 `facts`。动态文本只是证据/引述，不能变成程序指令。
5. **输出校验**：先校验整个模型响应，再运行原有拦截器、最终风险预算、止损单调性和交易所读回核验。

每轮只选取一次 profile，System/User 使用同一份配置；消息哈希与组成清单会保存。管理员页面的 `effective_templates` 也走同一个编译器，但动态值是预览占位符；真实发送内容以运行快照为准。

## 二、不再采用的引导方式

- 不再要求“空仓就必须挑一个开仓”。
- 不再要求模型报 78%~88% 或 82%~90% 等指定高分来通过门禁。
- 不再将微积分方向评分当作校准过的胜率，或宣称某种形态具有确定高胜率。
- 不再由各个风格层额外定义保证金比例、机械 ATR 止损倍数或另一套 JSON 输出结构。
- 不把没有新闻解释为市场平稳，也不把缺少聪明钱数据显示为默认 50% 多头。

全部 `WAIT` 合法。存在轻微分歧不意味着永久禁止交易，但必须解释为何候选仍成立；解释不了则等待。数学观察继续保留，证据组不代表统计独立。

## 三、开仓候选必须提供什么

除原有 action、价格、confidence、summary_reason 外，增加：

| 字段 | 校验要求 |
|---|---|
| supporting_evidence | 至少两条、至少两个审计组；其中有 structure/momentum/flow 之一 |
| counter_evidence_status | `observed` 或 `none_observed`，不能省略 |
| counter_evidence | 观测到反证时引用真实字段，并逐条给出 why_not_fatal；没有时明确空列表，不编造 |
| uncertainty | 明确残余风险，不得空白 |
| invalidation | 给出条件、依据周期和价格；价格必须对应 stop_loss_price |
| valid_for_seconds | 1~300 秒的整数，不能用布尔值或无限期限 |

引用是 JSON Pointer 风格的字段路径，例如 `/macro_4h`、`/price`、`/calculus/timeframes/1H/velocity`。输入会给出逐标的允许引用的 `facts`；模型需要回填原值和解释。

程序检查字段存在、数值匹配、重复引用、证据组、价格几何和有效期；不能拿其他标的或其他周期的数值冒充证据。价格同义字段若给出互相冲突的值会被拒绝，而不是偷偷选一个。

- 缺失/伪造证据、无失效条件等：该候选降级为 `WAIT`，附拒绝原因。
- 一个候选被拒绝，不自动否定其他独立合格候选。
- 正常 `WAIT` 不需要伪造价格、反证或无用指标。
- 合格候选仍可能被宏观、ADX、置信度门禁或净风险预算拒绝；`contract_valid=true` 不等于订单获准。

**有效期指“准入新提交”的期限，不是交易所挂单的自动撤单时间。** 到期后缓存读取与最终入场闸门拒绝该候选；已挂订单继续由既有挂单生命周期管理。`invalidation.condition` 是可审查假设，不是任意表达式/脚本；实际保护触发机制由执行器和交易所决定，不能通过自然语言改成等待收盘、延迟止损或取消保护。

## 四、持仓管理、撤单和严格 JSON

- `CLOSE_MARKET` / `UPDATE_SL` 需要证据引用、原因和合法分数；缺少证据降级 `HOLD`。
- `CANCEL` 必须针对输入中确实存在的订单，引用当前事实并给出原因；否则降级 `KEEP`。未知/重复订单身份会拒绝整份响应。
- 重复 JSON 键、NaN/Infinity、根结构/版本错误等会拒绝响应。
- 为兼容提供方，可以接收完整包裹一个 JSON 对象的代码围栏；不接受对象后附加解释文字。
- 单模型与 CIO 输出在任何模型指示的写入之前经过同一个校验器。
- 每个获得执行锁的新推理周期先清空旧开仓/持仓建议缓存；失败后不能复用上一轮仍“看似新鲜”的指令。
- 根协议不合格与接口 HTTP 503 是不同错误，会分开记录。

独立持仓保护、原有 fail-closed 退出以及写入后读回确认不依赖模型许可，继续有效。不新增下单、撤单、改单或平仓的盲目重试。

## 五、已有用户配置如何处理

**不直接重写用户保存的方案或覆盖文件。**

- `legacy_trading_prompts.json` 仅记录提交 `173884e` 中已知旧内置文本的哈希，不收集用户私有文本。
- 确认是旧内置引用时，运行和编辑器投影采用新基础规则，并在 manifest 标记 `legacy_builtin_reference_refreshed`；原配置文件保留。
- 真正自定义的安全内容保留为低优先级偏好；原来编辑过的 base 内容在编辑器投影中明确作为用户偏好，而不是新系统授权。
- 识别到强开单、指定高分、绕过风控或密钥等显式冲突时，不把该内容传给模型；保留原文件并报告冲突。
- 当前方案发生冲突或挂单快照无法核验时，不发起这轮付费模型推理，不新增风险；独立保护继续。
- 新的冲突编辑在保存/启用接口返回错误。客户端伪造 `locked=true` 不能提升自定义文本权限。
- 过长偏好会明确拒绝，不静默截断后继续交易。

自然语言里的风险数字不会自动改写执行器参数。需要硬预算时应修改经过验证的风险配置，而不是依赖一句提示词。显式冲突扫描不是完整的自然语言语义证明，也不能保证模型永不受干扰；真正的动作边界仍由程序和交易所核验提供。

## 六、投委会与影子研究

研究员和 CIO 的角色偏好只放在 User 层，不再在 System 后追加“特别授权”和另一套发单规则。角色内容冲突会在启动额外模型调用前拒绝；原角色文件不自动覆盖。

影子研究使用相同基础规则、字段定义、事实目录和输出校验。每个消融组只提供该组的实际字段；移除微积分或盘口后，不允许引用被移除的字段。确定性非 LLM 基线保持研究基线身份，不伪装成模型输出。

提示词、校验代码或组合规则改变后，影子策略指纹会变化，旧新实验不能混作同一个冻结版本。研究工具仍不会自动提升生产策略，也不会在本次改造中自行启动付费采样。

## 七、审计与验收

后台 `/api/v1/admin/prompt-library` 与旧版 `/api/v1/admin/prompts` 均使用相同编译器。旧版覆盖页会区分 System/User，不再把用户覆盖文本伪装成系统授权。新增可读组成信息：

- `composition`：profile ID/哈希、System/User 哈希、层次顺序、allow_open、兼容刷新/冲突原因。
- `snapshots.composition`：最近实际组合清单。
- `snapshots.output_validation`：pending / blocked / unavailable / composition_rejected / rejected / validated，以及逐候选拒绝原因。

投委会额外的角色/同伴上下文是独立附加消息，其 System/User 哈希分别记录在 transcript 中；主脑快照是基础消息，不冒充所有角色的完整请求。

后台 `/api/v1/admin/council/test` 不再伪造“实时”余额、持仓、行情或固定历史时间。自由文本测试输入明确标记为 `unverified_test_text`，没有已核验事实时只允许 WAIT，返回 `executable=false`。它只用于协议/连接诊断，不执行交易。

运行文件：

- `data/ai_brain_last_prompt.txt`
- `data/trading_prompt_manifest.json`
- `data/trading_output_validation.json`

离线测试入口：`python scripts/run_tests.py`（Linux/WSL 的隔离副本）。测试覆盖合格候选、全部 WAIT、引用造假、反证缺失、失效价不一致、过期、未知撤单、用户层注入、旧配置不被覆写、预览/实际消息一致以及无效响应不会触发模型指示的写入。

这些校验证明的是结构、来源引用和执行边界，不证明模型的解释正确、因果成立或策略具有正收益。真实模型的协议遵循率和交易效果仍需后续 DEMO/影子验收。本次不修改凭据、不切换 LIVE、不部署服务器。
