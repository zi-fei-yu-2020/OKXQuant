# 账户中心与独立资讯连接

## 当前交付边界

本地新增 `/admin/accounts` 账户中心、独立资讯读取、账户身份与绑定版本校验，以及 OAuth 原生令牌/Bearer 读取适配。保留现有交易 Key 与交易保护路径，不自动迁移、解绑、换号、切实盘或安装任务。

**没有完成真实 OAuth 授权，也没有执行 OAuth 下单/撤单/平仓验收。** OAuth 交易绑定和写请求明确拒绝；只有通过实际能力验证后才能考虑移除 Key。当前不是“纯 OAuth 已上线”。

## 用途分离

- `demo`：模拟盘交易用途，只使用显式绑定的该环境连接。
- `live`：实盘交易用途，必须明确确认切换；保存连接不激活交易。
- `news`：普通市场资讯用途，仅允许 GET 新闻搜索和币种情绪接口，不能读取交易账户接口或执行订单操作。

资讯失败不尝试交易 Key，不拿模拟盘 Key 伪装成普通市场 Key，不自动回退到其他 OAuth 或交易环境。

资讯传输依据已核对的官方 `@okx_ai/okx-trade-cli@1.4.5` 请求契约：`/api/v5/orbit/news-search` 与 `/api/v5/orbit/currency-sentiment-query`。普通市场资讯不是实盘下单。未修改官方 CLI 的 DEMO 禁止检查。

## OAuth 实现与限制

- 后端使用官方 `okx-auth` 原生程序，不通过浏览器收集令牌。
- Linux/WSL 令牌读取遵循官方 fd3 协议，随后使用 Bearer HTTPS；不反复启动 Node CLI，不解析用户粘贴的令牌。
- 每个连接使用独立受管理 HOME/配置目录，清除继承的 API Key、Profile 与会话 keyring 环境变量。
- **独立目录不是原生多账户并发认证的实测证明。** 每次资讯/账户读取前使用同一个令牌核验 UID，不匹配即失败；OAuth 自动交易始终关闭，避免原生登录态隔离未知时影响仓位保护。
- 令牌仅在后端内存短暂缓存，不进入 API 响应、日志、浏览器存储或本系统账户配置文件。
- 资讯通道的程序权限是只读；若官方 OAuth 默认授予更广权限，不能声称令牌权限已被本系统缩减。
- 当前传输仅对 Global 站点实现。EEA/US/TR 可以保存站点信息，但检查会明确报告未验证，不偷偷换成 Global。
- 本轮未实现 Windows 原生命名管道适配；后端 OAuth 传输使用 Linux/WSL。Windows 浏览器可以正常使用后台。

### 原生组件前提

官方 `okx-auth` 需要安装在**实际运行后端的同一容器/用户环境**下，默认位置为该用户 `.okx/bin/okx-auth`。本机授权不等于服务器授权。

安装参考：先检查官方 CLI，再使用官方 `okx auth install`。本轮没有执行安装或官方登录。若组件缺失，界面显示可理解的错误，不把它当成已登录。

## 连接生命周期

1. 新增候选：OAuth 或 Key；不会替换当前连接。
2. OAuth 在官方页面人工完成授权；账户中心只展示公共授权地址、用户码和有效期。
3. 对目标环境做只读探测：账户身份、余额、持仓、在途订单、保护单、持仓历史、账单；普通市场另外检查资讯能力。
4. 绑定用途前核验最近5分钟的能力结果。Key 交易用途保留已有签名执行适配器；读取通过不等于新 Key 的交易权限已经实际测试过。
5. 交易换号/解绑/环境切换检查旧账户与目标账户持仓、普通挂单、OCO、条件单、触发单、移动止损、冰山/TWAP等订单，并阻止未确认交易意图、正在运行的策略周期和同步任务。
6. 没有可靠空仓/无挂单证据就拒绝操作。不会为了换号自动平仓或撤单。

确认短语分别是 `BIND DEMO/LIVE/NEWS`、`UNBIND DEMO/LIVE/NEWS`、`ACTIVATE DEMO/LIVE` 和 `DELETE CONNECTION`。

授权完成不自动交易；**切换当前交易环境会影响后续已经配置的策略任务**，界面要求额外确认。系统不同时运行两套交易实例。

## 账户身份、预算及旧任务

- 认证连接ID与账户UID、交易环境分离。
- 同一账户更换 Key 时保留已知原风险/账本作用域，不用“换凭据”重置风险预算。
- 不同账户使用隔离作用域；金融缓存移到 `data/account-switch-archive/`，不删除历史审计。
- 绑定版本变化后，旧进程上下文、旧决策不能继续下单；版本校验与最终风险预检同时保留。
- 资讯绑定和草稿检查不改变交易绑定版本。
- 已由账户中心接管后，旧配置接口不能覆盖交易连接；解绑后的环境不会回退旧 Key 或全局 OAuth。
- 仅有通用旧 Key 时不会把它同时导入模拟盘和实盘。历史 OAuth 连接无法核验时不会将它假定为空仓。

## 凭据与解绑语义

连接配置使用现有 Fernet 密钥加密保存在 `data/account_connections.enc`，文件权限600。API只返回连接元数据和能力状态，不返回 Key、Secret、Passphrase 或 OAuth Token。

解绑仅解除用途关联，不宣称撤销交易所授权。删除未绑定连接会清理本系统受管理目录和内存缓存，但仍提示用户到 OKX 核对官方授权/Key 撤销状态。授权进行期间不能删除目录，避免异步授权落盘留下孤立凭据。

真实多账户 OAuth 的原生凭据存储/撤销语义仍需在人工授权后验证，不伪造“官方已撤销”的结果。

## 真实资讯状态

`news_sentiment.json` 新增：
- `connection_id`、`connection_generation`、`source`；
- `last_attempt_at`：本轮尝试时间；
- `last_success_at` / `updated_at`：全部分区最近成功时间；
- `sections.latest / important / sentiment`：各自成功时间、状态及脱敏错误；
- `connection_status`：fresh / partial / unavailable / unconfigured / binding_changed。

失败可以显示同连接的旧缓存，但不刷新成功时间。换连接/重新授权不复用旧授权的内容；发布前再次检查绑定及授权版本。缺失情绪显示未知/`--`，不填50%或零分来假装正常。

模型输入只接受可核验、足够新鲜的资讯分区；旧版缓存、失败或过期分区不能作为当前宏观事实。没有新闻不等于市场平稳。原有黑天鹅检测只处理新鲜且非未来的新闻，持仓保护逻辑保持独立。

## 完成真实恢复所需的人工步骤

代码发布并具备原生组件后：
1. 账户中心添加“资讯 OAuth”候选。
2. 点击官方授权，在 OKX 页面人工完成。
3. 点击“检查普通市场/实盘”，确认身份与资讯接口通过。
4. 将该候选绑定到“市场资讯”，再点击读取资讯。
5. 确认最后成功时间推进、失败状态消失；模拟盘交易绑定应保持不变。

随后才能进一步检查 OAuth DEMO 私有读取、授权并发隔离及完整交易保护闭环。当前代码没有开放 OAuth 交易写入或自动交易绑定，也没有移除 Key 入口；本轮不能把模拟接口测试宣称为真实 OAuth 验收通过。
