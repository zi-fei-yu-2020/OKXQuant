# 当前交易环境的标的支持状态

行情可见性不等于可交易性。以 WLD-USDT-SWAP 为例，普通公共市场可以有价格与 K 线，而当前模拟盘合约目录没有这个标的。

## 用户界面

- 标的池管理显示当前已生效环境，以及每个标的的支持状态；提供重新核验入口。
- 前台雷达和详情共用 `InstrumentSupportNotice`：支持、不支持、暂不可交易、待确认四种状态。不依赖颜色或鼠标悬浮传达信息。
- 不支持或未确认时保留公共行情观察，隐藏可执行买卖建议、置信度以及可能误导的默认 ADX/聪明钱值，不将 0/50 当作有效信号。
- 切换环境前以目标环境目录预览现有池。存在观察/待确认标的时，组件弹窗列出具体合约；取消不提交配置。LIVE 原有确认短语仍保留。
- 不自动删除、替换标的，不偷偷切换官方指标的数据来源。

## 后端语义

`scripts/instrument_support.py` 从当前环境的完整 SWAP 目录判定，而不是硬编码 WLD。

| 状态 | 含义 | 新开仓/加仓 |
|---|---|---|
| supported | 目录存在且为在线 USDT 合约 | 可进入后续原有风控，不保证下单成功 |
| unsupported | 成功获得完整目录，但其中无该标的 | 禁止 |
| unavailable | 目录存在，但交易状态或结算币种不满足要求 | 禁止 |
| unknown | 目录尚未核验、过期或查询失败 | 暂停，不能误报为不支持 |

模拟/真实环境目录分开缓存，有效期最多 60 秒。使用公共采集层的并发、限频和请求去重。普通页面读缓存并后台更新，不阻塞原监控接口；显式核验使用有界请求。后台失败有短暂退避，避免页面轮询造成请求风暴。

## 交易安全边界

- AI 开仓候选仅包含已核验支持的标的；已有持仓对应标的即使未确认/不支持，仍保留给持仓管理，并向模型注明禁止增加敞口。
- 执行循环跳过不允许新增敞口的标的。
- `submit_protected_limit_order` 在真正发送开仓/加仓指令前再次核验；未知也阻断。取消、止损、平仓路径不经过这道新增风险检查。
- 这不意味着切换到另一环境后仍同时管理两个账户，也不意味着交易所一定接受保护订单。环境切换不会自动平掉另一环境的仓位，用户应另行确认。

## 测试

覆盖目录缺项、查询失败、停牌、环境隔离、缓存时效、未知状态、新增池项、已有仓位保留、开仓边界阻断和合法保护订单参数、API 鉴权及只读预览。

Windows 桌面 Edge/Playwright 在隔离 API 测试数据下检查亮/暗模式、1440/390 宽度、详情提示、环境切换取消/确认及添加错误组件反馈。测试不会向真实服务器提交配置修改或交易操作。生产接口状态另行只读核验。
