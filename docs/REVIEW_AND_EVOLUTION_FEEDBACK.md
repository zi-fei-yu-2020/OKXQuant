## 范围与发布状态

- 本地 `dev` 从 `05f50f1` 快进到远程 `22a5e9c53f46a05960764016d269c22e9cf5e762`，涉及 84 个变更文件。
- 重点审查：成交费用与台账口径、300U 执行预设、保护与入场回归、复盘/记忆注册表的合并兼容性、前端交易记录和相关文档。
- 本轮修复仅在本地。未提交、推送或部署；没有调用线上模型或交易接口，没有自动发布记忆，也没有修改风险预算、杠杆和交易开关。
- 这是重点审查和回归验证，不是对全部代码无缺陷或策略盈利的保证。

## 确认并修复的问题

| 问题 | 影响 | 修复 |
|---|---|---|
| 上游历史账本缺失金额补零，缺失保证金补 500U | 下游即使保留 null，也可能收到伪造的完整数值 | 只接收有限的真实字段；官方净额明确未知时不回退毛利；仅完整费用分量允许派生净额；去掉虚构保证金和猜测 ROI |
| 复盘未知净额回填旧 pnl、缺失费用补零、返佣取绝对值 | 样本、手续费及盈亏归因失真 | 排除未知/未结算/重复/异账户样本；保留费用符号与原始精度；持平不算亏损；无亏损分母不制造利润因子 99 |
| 复盘未接入已有开仓决策归档 | 模型只能从结果猜原因，无法使用实际已保存的历史指标 | 精确核验同账户成交 billId、clOrdId、意图和决策；校验摘要、标的、方向及时间；只提供原始开仓快照 |
| 成交费用归档读取未核对事件摘要 | 损坏的归档内容可能仍被标为已核对 | 读取时验证 SHA-256，失败时费用保持未知，不新增网络重试 |
| 回测完整时间轴校验发生得太晚 | 截取验证/测试窗口后，过长标的序列或损坏的训练前缀可能被忽略 | 切片前核验完整时钟、唯一时间标记、连续性和所有标的长度/时间一致性 |
| 合并测试和文档仍依赖旧记忆直写入口 | 测试失败，页面说明与实际审核机制冲突 | 保留禁止直写的安全限制，更新测试和文档到 memory_registry.db |
| JSON 新报告与派生 Markdown 可能不同步 | 页面可能把旧原文与新报告状态混用 | 原文嵌入原子保存的报告 JSON；Markdown 文件只作为旧报告兼容来源 |

官方结算数值现在保留原始精度，页面仍按展示精度格式化。例如 `2.77586` 不在存储时截成 `2.78`，但两位小数展示仍为 `2.78`。

## 交易记录界面

- “费用明细”使用独立第九列，表头、单元格和按钮居中。
- 复用 AppButton/AppDialog、界面语义色与 Receipt 图标，按钮点击区域至少 44px 高。
- 持仓和待结算行保留列占位，不提前显示已结算费用按钮。
- 手机仍在表格自己的区域横向滚动，不把整页撑宽。
- 价格、保证金与盈亏区分真实零值和未知值。

## 本轮实际完成的自进化能力

原有审核发布与版本回滚继续保留。本轮增加：

1. 每次复盘自动生成程序计算的费用、返佣、净额、毛利被摩擦抵消的样本统计。
2. 自动尝试关联历史开仓快照，明确 `linked / partial / unobservable`。找不到精确链路时，不按时间接近或同标的强行匹配。
3. 只有全部开仓链路可核验且版本一致的样本，才进入按记忆指纹、代码版本和执行预设分组的结果反馈。
4. 模型收到真实可观测指标和程序统计；候选需要说明适用条件、反例、单变量对照、费用后指标和撤回条件。
5. 前台和后台共用“自动证据反馈”组件；报告、候选和有效记忆不混为一谈。
6. 新复盘协议会让旧协议成功报告重新接受一次复盘；同协议、同证据和同记忆版本的重复任务仍跳过额外模型调用。

**这不是完整自动策略晋级。** 分组统计没有消除市场状态、模型、成交质量等混杂因素；历史关联也不是因果证明。不以这些分组统计自动发布经验、扩大仓位或提高杠杆。旧记录缺少快照或客户端订单关联时，无法事后补造。

## 完整受控自进化的后续方案（尚未实施）

1. **冻结可执行实验**：将单变量假设绑定明确的候选版本、基线、适用环境和退出条件；不允许任意执行模型生成的 Python。
2. **前向对照**：在同一行情时点采集基线/候选的决策，并保存生成时间、数据截止时间、模型/提示词版本与调用费用。事后重放模型不能冒充前向决策。
3. **统一执行口径评价**：使用相同的报价、手续费、滑点、资金费和风险预算，对照费用后收益、回撤和成交结果。现有 research_lab 可用于离线评价，但尚未自动接通完整实验编排与推广。
4. **模拟盘灰度**：只有经过明确授权的候选在有限预算/标的范围内试运行；不自动切换到实盘，不增加整个账户风险上限。
5. **晋级与退出**：足够的新样本支持后才允许晋级。预先约定异常、回撤、数据中断及相对退化的退出条件，保留上一版本和当前持仓保护。实盘自动晋级必须单独授权。

为了避免重新引入长时间 WAIT，这些研究约束不附加为现有交易的新评分门槛。未通过研究的候选不改变当前已批准策略。
