# 通用模型传输与能力验证

## 接入流程

1. 在后台“模型与供应商”保存供应商地址、凭据、协议和模型；不要把另一个供应商的 Key 借给新地址。
2. 供应商详情中的“响应方式与连接稳定性”使用**已保存配置**，不使用尚未保存的表单草稿。
3. 默认 **自动选择**：已有当前连接的流式验证记录时使用流式，否则维持非流式兼容并提示“未验证”。系统不在启动、打开页面、保存设置或每轮交易时偷偷发起付费探针。
4. 超级管理员点击“验证流式”或“验证非流式”并确认后，才发送一次固定、小型 JSON 探针。探针保留模型/思考配置，可能产生费用；短输入不代表所有模型只消耗少量思考 Token。
5. 验证接口立即返回任务 ID，页面轮询结果，不让一个管理 HTTP 请求等待几分钟。通过后，自动模式按能力记录选择流式；失败不自动换模型、降思考强度或重发另一种模式。
6. 不支持流式的服务可以显式选“非流式兼容”。这仍无法绕过第三方代理自身的静默超时，界面会提示限制。

普通管理员可读取配置和状态；修改、付费探针、旧式连接测试和携带已保存凭据的远端模型发现要求超级管理员。

## 支持范围

本轮支持现有三种标准协议的同步 JSON 与 SSE 接收：

| 协议 | 完整性边界 |
| --- | --- |
| OpenAI Chat Completions 及兼容端点 | 单个选择的正常 `finish_reason=stop`，流式还要求 `[DONE]`；拒绝工具调用、拒答、截断和结束后已收到的矛盾数据 |
| OpenAI Responses | `response.completed`、正常状态与结构化输出一致；`output_text` 不得与 `output` 冲突，文本 done 事件不能代替整个响应完成 |
| Claude Messages | 完整的 message/block 生命周期、正常 stop reason、`message_stop`；thinking 与 signature 是单独内容/元数据，不能混入交易 JSON |

原生 Gemini、Bedrock、特殊 Azure 路由/认证或厂商自定义协议不因此自动获得支持。可以使用其真正兼容上述标准的端点，或新增显式适配器；不能只根据模型名字猜测兼容性。

短探针验证本次协议和小型 JSON，不保证任意上下文长度、输出预算、思考参数、供应商负载或所有长请求都正常。真实交易还需通过原有 JSON 契约、时效、账户绑定和风控检查。

## 超时与资源边界

默认连接 10 秒、响应头/首包 150 秒、流内空闲 90 秒、整轮总时限 180 秒。最终预算取配置与调用任务预算的较小值：当前交易主脑及能力探针还受 180 秒调用上限限制；调大供应商总时限不自动放宽交易时效或调度预算。

- 心跳更新“连接有活动”，不会延长绝对总时限，也不是有效决策。
- 记录首包与首个模型文本/思考内容的时间；role、usage、签名和心跳不能冒充生成内容。
- 单事件上限 1 MiB，默认解码响应上限 8 MiB；支持分块 UTF-8、CR/LF、注释心跳及压缩响应。
- 生产同步调用一条请求只启动一个隔离传输进程。凭据和请求走 stdin，不在命令行或临时文件；子进程只继承必要运行环境、代理和 CA 设置。
- 独立截止监督器可终止卡在输入管道、导入、DNS、读流或执行器退出的子进程并回收。计时包括启动及 IPC；OS 调度/回收有小量开销，并记录实际耗时。
- `request_inference_async` 供受控异步调用/测试使用，其外层执行器生命周期由调用者负责；项目的生产调用走隔离同步入口。

## 能力记录与任务安全

`data/llm_transport_settings.json` 私有保存供应商策略及验证摘要。记录绑定供应商、模型、实际地址、凭据摘要、协议、思考强度及推理类型；不保存 Key、提示词或模型正文。连接变化使旧记录失效。

`data/llm_transport_verification_jobs.json` 是有期限的跨进程任务记录。同一连接/模式的在途验证去重，最多两项并行；重启不重放模型请求，过期任务标为结果未知。验证记录发布与任务租约检查共用锁，旧任务不能覆盖新任务的结果。

临时网络故障不撤销此前确认过的协议能力；最近复检失败会独立显示。只有明确的 `stream` 参数不支持响应才标为“不支持”，普通 524/超时/断流不能据此推断。

委员会按显式配置仍可安排多个专家及仲裁请求，这不是 HTTP 重试。角色模型现在按供应商与模型 ID 绑定；旧配置仅在同名模型唯一时兼容，歧义或不存在时拒绝调用，不能偷偷换成全局模型。最终委员会裁决失败后也不再补发额外单模型请求。

HTTP 200 不等于成功决策。半截 SSE、缺少结束标记、响应自相矛盾、拒答、超出预算及不完整 JSON 都不能进入交易执行。524/断流等不明确结果不会自动重发；取消本地请求也不能保证供应商停止计算或不计费。

## 观测位置

- `/admin/llm`：策略、能力状态、显式验证结果与高级超时。
- `/admin/agents`：真实模型调用的传输详情，包括首包、首个内容、最长间隔、心跳、HTTP 状态、失败阶段和经过白名单校验的 Request ID / CF-Ray。
- 模型调用数据库用独立 `model_call_transport` 表保存摘要；旧调用显示未采集。缺失 Token 用量保持未知，真实零值保留为零。

## 部署与验收

没有硬编码当前服务器、域名或 new-api。当前部署的 new-api 已只读核对为启用 30 秒心跳；本轮不修改网关设置。框架支持供应商发送的合法心跳，但客户端无法替不发送数据的外部供应商伪造下行保活。长期静默的服务仍需供应商/其网关支持或选择不经过该限制的链路。

本地验收包括三协议解析、HTTP 错误/中断/截断/慢首包/持续心跳/总时限、压缩、过期探针、凭据隔离、前后台权限、确认取消与页面切换。`scripts/check_llm_transport_process.py --long-seconds 135` 是不调用任何模型的本地回环真实 HTTP 长流测试，不能冒充实际供应商的 Cloudflare 长流验收。

生产更新保留账户、模型、思考强度、交易参数和运行配置；新能力首次默认为未验证。受控维护中完成当前供应商的显式验证后再恢复原自动开仓状态；保留旧镜像和传输设置备份以便回滚。
