# 策略风险与研究引擎 v2

交易提示词的完整分层、证据输出和兼容规则见 `docs/TRADING_PROMPT_CONTRACT.md`。当前交易入口要求 `trading-evidence-v1` 校验通过及候选未过期，不接受旧版未校验建议直接开仓。

本次实现四个阶段的工程能力，不将工程测试通过等同于策略已被证明盈利。新增风控会比旧版严格，开仓数量/频率可能下降。运行凭据、DEMO/LIVE 选择和用户保存的提示词方案不会被迁移脚本改写。

## 1. 确定性执行约束

### 云端止损只能单向收紧

- 多头：`旧云端 SL < 新 SL < 当前价`；空头相反。相同值不重复改单。
- 原有盈利空间/ATR 缓冲约束继续有效。
- 修改指令只发送一次，包括返回不确定时也不重发；之后读取同一个 algoId 确认。
- 只有确认交易所新止损已经生效才推进 `cloudProtection`/`exchangeStopPx`。
- 本地阶梯线用 `localTrailingStopPx` 区分；本地更严格不代表云端已同步。
- 新发现的已有持仓先读取原有完整云端保护，不再用“此刻 ATR”虚构原始止损。原始保护无法确认时保留 fail-closed 安全退出；退出失败不得删除跟踪状态。

### 最终订单风险闸门

`scripts/entry_gateway.py` 是受保护限价入场的最后一步，位于任何模拟盘价格适配之后：

1. 验证同账户、同标的、同方向的持久化决策证据和 300 秒数据时效。
2. 对旧的不确定订单按 client ID 只读对账。不能确认时阻止新的风险，而不是假设订单未成功。
3. 读取实际合约元数据、账户权益/可用保证金、持仓、挂单、保护单和真实杠杆。
4. 以最终 entry/SL/TP 计算净成本后 R:R 和预计止损风险，按 lotSz 向下取整；不足 minSz 就跳过。
5. 检查单笔、组合、同向、分组风险和单币保证金余量。所有未成交入场订单参与风险预留。
6. 再读持仓检查核验期间数量/持仓身份是否变化；变化则暂缓本轮入场。
7. 在 SQLite 提交唯一入场意图后，带生成的 clOrdId 发送原有单次限价单。相同决策不能重复发送。

仅支持可验证的线性 USDT 合约元数据；缺少实际杠杆/步长等字段时不能用模型值或默认一张替代。模型保证金只影响请求数量，不能突破最终风险预算。止损/费用/滑点估计不构成极端跳空或强平损失的绝对保证。

### 风险配置

默认读取 `data/risk_policy.json`；文件不存在时使用 `Policy` 默认值。提供示例：`docs/risk_policy.example.json`。**示例是工程默认值，不是经过收益优化的推荐参数，不会自动复制到运行目录。**

| 参数 | 默认值 | 含义 |
|---|---:|---|
| per_trade_equity_pct | 0.005 | 单笔预计风险同时受权益 0.5% 和标的美元预算约束 |
| portfolio_stop_pct | 0.03 | 组合预计止损风险上限 |
| direction_stop_pct | 0.02 | 单方向风险上限 |
| group_stop_pct | 0.02 | 分组风险上限 |
| daily_drawdown_pct | 0.03 | 北京时间当日观测权益回撤门禁 |
| peak_drawdown_pct | 0.08 | 经外部资金流调整的历史观测高水位回撤门禁 |
| single_asset_margin_usdt | 600 | 单币已有及新增保证金合计上限 |
| available_margin_fraction | 0.8 | 不用尽全部可用保证金 |
| minimum_net_rr | 2 | 成本缓冲后的最低 R:R |
| max_leverage | 5 | 读取到的真实交易所杠杆上限；不代替交易所设置杠杆 |

目前保守地将全部加密合约视为一个风险组；尚未用短期样本自动推断“独立风险组”。因此多个上限取最严格者。原有固定日亏损门禁和加仓门禁仍然保留。费率、滑点只是可配置的预算假设，成交账本使用交易所实际费用。

## 2. 可信回测、净值与证据

### 回测

`scripts/backtest_engine.py`：

- 缺失行情返回 `unavailable`，不再生成正弦/合成价格冒充正式行情。
- `signals=None` 明确标记为简化均线基线，不是假称生产 LLM 回测；`signals=[]` 保持零信号。
- 冻结信号在 K 线收盘后可见，订单最早在下一根执行。
- 同根 K 同时涉及止损和止盈按不利的止损路径处理；保本线从本根收盘计算，下一根才生效。
- 限价采用穿价/市场化判断、成交量参与率与部分成交模型；缺成交量不假定限价全额成交。
- 附带 TP/SL 按市价退出处理，计 taker 费率和不利滑点，与线上 `tpOrdPx/slOrdPx=-1` 口径一致。
- 期末持仓按收盘价盯市，不隐藏浮亏；组合使用共享现金与风险预算，不使用 BTC 曲线代替组合曲线。
- R 分母保存初始风险，不随保本线移动而归零。年化使用实际 bar；不可定义的指标用 null，而不是 99。
- 资金费率需要归档输入在每根 K 明确提供 `funding_rate`（无结算则为 0）；缺失时标记 `exploratory_missing_funding`。
- 信号可携带已核实的 `model_cost_usdt`，包括 WAIT 调用；回测将这些费用从经济净值扣除。交易级胜率/Profit Factor 不含共享模型开销，最终净值包含已知开销。缺少模型真实账单时不能证明 LLM 带来净增益。

这是保守的执行重放模型，不是完整的交易所排队、强平、所有线上微结构事件/LLM 持仓管理行为的精确模拟。最新 100/300 根 K 线不足以证明长期策略有效；正式对比需要更长的归档窗口和冻结前向决策。

### 证据与实际账本

`data/strategy_evidence.db`（SQLite WAL、完整同步）：

- 决策：模型、策略版本、提示词指纹、数据时点、特征、最终决策 ID。
- 持仓管理/撤单提议与提交状态；入场意图、计划数量、实际风险预算、clOrdId 和订单回执。
- 真实 fills、仓位结算回执、权益观测、保护核验和改单确认。
- 新增风险的证据写入失败时阻止开仓；安全退出不能因审计存储失败被阻断。
- 分页成交按批次事务归档，幂等去重；不完整分页保留游标继续同步，不冒充完整历史。
- 交易所历史接口有保留范围，首次归档只证明已获取的范围，不宣称账户终身记录完整。

`sync_full_ledger.py` 优先使用交易所 `realizedPnl`；缺失时明确使用 gross + signed fee + funding。开平仓费用不再凭空各分一半，未获得实际分配时字段为 null。查询失败保持原账本；已归档的旧已平仓记录不会因接口只返回最近 100 条而丢失。

自动复盘只消费明确 `status=closed` 的记录。新心法写入 `memory_candidates.json`，运行 JSON/Markdown 记忆不自动覆盖，复盘文本单独写入 `self_improvement_review.md`。候选规则缺少逐条支持交易 ID 或前向证据时不能认为已验证。

## 3. 独立持仓保护与数据时点

新增 scheduler jobs：

- `position_guard`：每 60 秒，专用单线程执行器，不与 LLM/新闻任务争抢线程池。
- `evidence_sync`：每 300 秒，只读归档成交，不执行交易。

主交易仍每 15 分钟决策。主交易、独立风控、模型撤单以及后台原生交易写入共用 `.position-writer.lock`；锁可重入。主交易在模型推理阶段释放写入门禁，但保留自身周期锁；模型返回后重新获取门禁、重读持仓/跟踪，避免用推理前的仓位执行。

独立风控不调用模型、不下开仓单。它核验全部已持有的可管理合约，不局限于当前观察池；有静态凭据时持仓/权益读取走原生 REST。公共数据失败不应绕过私有保护核验。已有 long/short 模式受支持；其他持仓模式报告不支持，不把方向猜成多或空。`OKXQUANT_POSITION_GUARD_ENABLED=0` 可关闭新增独立作业，但不关闭原有主循环保护；默认值为 1。

权益包含浮盈亏；USDT 转入转出调整基线，不算策略盈利。历史资金流水分页不完整、未识别账单类型或非 USDT 外部流量会阻止新增风险并要求对账，保护核验仍继续。首次启用和每日首次观测是明确的观测基线，不虚构启用前或未采样的午夜权益。更换账户凭据作用域后须重新确认基线。

`signal_data.py` 对策略 K 线检查确认收盘、时点、缺口、重复和价格有效性；原始盘中行情读取接口保持独立。每轮采集固定 as_of。技术指标以已确认收盘 K 的开盘时间作为回看上界，保守情况下可能多滞后一根，不偷用当前未收盘 K。订单执行使用新鲜报价，而不是拿闭合信号价格充当实时价。

## 4. 前向影子消融与时序样本外评估

`shadow_research.py` 只收集影子决策，不调用会撤单/下单的完整交易脑循环。

内置比较组：

1. 确定性趋势基线；
2. LLM；
3. LLM + 微积分；
4. LLM + 微积分 + 盘口；
5. LLM + 微积分 + 盘口 + 已有记忆。

每组使用同一初始快照，只提供该组允许的字段。缺失字段不是中性值。任何组失败都记录不完整，不偷偷生成假 WAIT；存在不完整采集时不能宣布已证明增益。比较的是显式特征提供方式，不声称价格派生指标是统计独立信息。

示例命令（Linux/WSL，项目根目录）：

```bash
# 仅采集公共特征快照，不调用模型，不交易
python scripts/shadow_research.py --capture

# 明确允许模型费用：同一轮额外调用四次模型，仍不交易
python scripts/shadow_research.py --capture --allow-llm-cost --scope shadow:study-001

# 将前向归档事件与事后获取的闭合K线归档对齐
# 文件包含 candles 映射及实际合约 metadata；真实资金费应完整归档
python scripts/shadow_research.py --export-candles data/research_candles.json \
  --scope shadow:study-001 --bar 1H --cost-ledger data/model_cost_ledger.json \
  --output data/research_dataset.json

# 完全离线评估；不改运行策略
python scripts/research_lab.py --input data/research_dataset.json
```

模型费用账单是以 `<cohort.available_at_ms>:<variant_id>` 为键、实际 USDT 等值费用为值的 JSON 映射。一次模型调用覆盖多个标的时，导出器均摊到该次决策各标的，合计不变。未提供账单时保留 null，不假设模型免费；采集器不读取用户其他服务的管理账单接口。

研究数据每根 K 的 `ts_ms` 表示闭合/决策时点，而非开盘时点；每条信号含 `generated_at_ms` 和 `features_as_of_ms`。模型生成晚于本根闭合时点时，导出工具保守地放到下一可用闭合时点，重放再从下一根开始执行。不能用事后补生成的 LLM 看法冒充当时的信号。模型/记忆/策略变更需要独立分版本研究。

`research_lab.py`：

- 50% 训练区、25% 验证区、25% 未触碰测试区；输入候选必须提前冻结。
- 各组采用相同风险政策、合约元数据、资金费和成交模型。
- 配对分块 bootstrap 比较超额每期收益；固定 seed，并按候选数量调整检验阈值。
- 默认要求测试区至少 30 天、基线和候选各至少 50 笔已平仓交易。这只是证据门槛，不是充分盈利保证。
- 缺真实合约元数据、真实来源、资金费、模型费用或完整前向采集时标记 `insufficient_evidence`。
- 只有区间下界为正且回撤不比基线更差时才列为 `candidate_for_manual_review`；`auto_enable` 永远为 false。
- 保存输入哈希、源码哈希、评估配置、唯一运行哈希；CLI 将每次研究输入与结果归档到 `data/research_runs/<run_hash>/`，不只保留表现最好的一次。
- 反复研究后挑选版本仍可能过拟合，必须用新的未触碰时间窗口复验；不自动调整生产参数。

## 运维和验证边界

- 新增管理员只读接口：`GET /api/v1/admin/strategy/status`，沿用现有管理员认证。返回风险政策、观测权益、未决入场数量、最近风控、证据计数、候选规则和研究状态，不请求模型/交易所。
- 仅需检查时使用 `python scripts/position_guard.py --observe-only`。**不带该参数的脚本有权按现有安全策略改单/退出，不能当只读诊断运行。**
- 不确定入场无法在交易所查明时继续阻止新增风险，须人工核实，不提供一键“当作失败后重试”。
- 本版本不迁移用户凭据、不切 LIVE、不自动启用付费影子模型采集。
- 独立风控需要 Linux/WSL 的 OS 文件锁；测试使用 `python scripts/run_tests.py` 的隔离副本，禁止用真实账户跑 unittest discovery。
- 部署前必须备份运行数据/旧镜像，在无交易任务的窗口更新，先对 DEMO 做只读验收，再观察自然交易周期。本地离线测试不是已完成服务器闭环验证。
