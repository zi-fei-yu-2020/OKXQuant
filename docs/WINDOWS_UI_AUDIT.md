# Windows 桌面浏览器逐页复核

## 检查环境与范围

本轮使用 Windows 本机 Playwright，通过有界面的 Chrome 访问现有 `http://localhost:8080` 服务。没有启动模拟后端，没有使用虚构账户数据替代服务响应。只控制本轮创建的检查页面，未关闭用户打开的其他标签页。

逐页检查前台 6 个页面和管理员后台 16 个页面，各检查亮色、深色模式，共 44 个基础状态。除布局之外，还读取浏览器最终计算样式，检查真实文字、输入值、占位符与背景的对比度，以及控件名称、字段 ID 和接口错误。

> 这是对上一轮检查范围的补充和更正：之前的布局检查不能证明最终继承的文字颜色正常。实际页面仍存在 HTML body 固定深色类覆盖主题的问题，本轮已定位并修复。

## 已发现并修复

| 问题 | 修复 |
| --- | --- |
| `index.html` 的 body 固定为深色背景、浅色文字，覆盖主题基础样式 | 移除固定颜色类，让实际 body 的文字和背景跟随主题变量；增加 HTML 回归测试和浏览器实际颜色一致性检查 |
| 模型启用/禁用状态、能力标签、选中按钮沿用暗色用的浅色文字 | 改为双主题语义色，覆盖紫色、粉色、蓝色、警告与成功状态 |
| 模型能力文案不清晰，选中状态缺少辅助语义 | 使用“图像理解”文案，能力按钮增加 `aria-pressed` |
| 模型配置开关缺少可访问名称及一致的主题样式 | 使用 `AppSwitch`，保留原来的本地表单绑定，不自动保存 |
| 停用插件卡片整体透明，说明和可操作按钮也变得难读 | 不再整体降低透明度，以边框和明确状态保留启停区别 |
| 自进化基准/生效标签及审计详情对比度不足 | 使用语义色，移除不必要的文字透明度 |
| 表单标签未关联输入框、循环字段缺少名称 | 通过 `AppField` 自动 ID、关联标签和显式控件名称修复；模型密钥的显示按钮也有明确名称 |
| 插件源码编辑器缺少名称，函数说明过淡 | 补充编辑器名称并恢复可读文字对比度 |
| 确认短语说明未与输入框关联 | 关联确认消息和提示，保留原有确认规则与取消语义 |
| 外部 Google 字体加载在本机网络下可能延迟 | 移除外部字体链接，使用现有本地字体回退，不新增在线依赖 |
| Windows 服务打开提示词工作室、自进化时返回 500 | 将两个策略脚本的 `fcntl` 导入延迟到真正执行加锁时；只读提示词定义不再因 Unix 依赖而无法导入 |

## 业务与安全边界

- 没有提交保存配置、创建用户、下单、平仓、真实模型请求、通知、备份或恢复。
- 页面检查使用请求拦截防止误提交。供应商开关仅在未保存的表单中切换并恢复；模型能力只在未提交的新建弹窗中检查。
- Windows 的只读管理页修复**不是**交易引擎的完整 Windows 移植。执行时仍需要真实 POSIX 文件锁，不提供空锁或绕过实现。
- 新增回归确认：缺少 `fcntl` 时，任务必须在调用执行函数和访问锁文件之前失败。
- 管理密码未写入代码、文档或报告；截图和报告放在被 Git 忽略的本机目录。

- 44 个基础状态：实际主题颜色不匹配 0、文字/控件对比度问题 0、缺少名称的可见控件 0、重复字段 ID 0、整页横向溢出 0。
