# 未决开仓自动核对修复（2026-09-19）

## 故障

9 月 19 日 00:51 的 SUI 开仓提交未取得回执，意图保持 unknown。
随后查询返回 OKX 51603（订单不存在），但通用异常分支立即终止核对，
历史订单分支无法执行。该账户的新候选持续受阻，不是当天熔断。
原始提交 stderr 未留档，因此不能断言初次失败是网络还是业务参数问题。

## 恢复规则

- OKXAPIError 独立保留业务 code；只有 51603 或成功空响应进入缺单路径。
- 按交易所客户端订单 ID 与 instId 精确匹配，不依赖历史列表支持 clOrdId 筛选。
- 分页核对当前挂单、订单历史、成交历史，最后核对该币种持仓。
- 列表分页上限 5 页；每笔核对总预算 25 秒，单次读取不超过 8 秒。
- 至少等待 120 秒；超过安全历史窗口不以空结果解锁。
- 若已收到过明确订单受理回执，不以空历史记录抹除受理证据。
- 成交缺少客户端订单号且无法由已知其他订单归属排除、持仓非空、
  数据畸形、503、网络或权限错误，均继续保留占用。
- 全部必要证据通过后保留原 intent，将状态变为 not_found；含义是
  没有当前挂单/持仓或可定位成交，不宣称交易所从未受理过。
- 查到有效订单则按 filled/canceled/pending 等真实状态恢复。
- 不重发旧订单，不删除账本，不调整策略、杠杆或熔断阈值。
- 入口最终预检自动执行核对；核对完成后仍须通过完整的新候选授权。

## 可观测性

entry_reconciliation 记录结果、读取端点/行数及安全失败分类。
entry_submission / entry_rejection 留存脱敏的 CLI 退出码、交易所错误码、
异常类型与限长错误信息。凭据和 URL 不留存于这些失败诊断。

## 验证

新增缺单恢复、重复运行、终态受理、挂单/部分成交、分页上限、
网络/鉴权/503、成交归属不明、持仓非空、历史窗口、已受理回执保护、
错误码和凭据脱敏测试。使用 scripts/run_tests.py 的隔离快照运行，
不触碰生产数据。服务器恢复只执行 reconcile_intents，不调用下单主循环。
