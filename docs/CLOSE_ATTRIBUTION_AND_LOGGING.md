# 平仓来源与巡检摘要

## 本轮边界

仅本地实现与验证，不部署服务器、不改交易参数、不启用300U资金池。不修改平仓CLI命令，也不增加下单、撤单或平仓重试。

## 平仓来源证据

旧实现只匹配末次关闭前后5秒，且主要识别后台client ID和algoId，无法正确覆盖更早的分批止损与策略关闭。

新实现：
- 按持仓完整生命周期匹配实际成交的平仓订单，按ordId去重；部分成交后取消的订单按accFillSz计量，不能将请求数量视为成交数量。
- 后台保留client ID、关闭回执中的订单ID、有效算法单中的子订单ID，作为直接来源证据（verified）。止盈/止损依据算法触发侧，不依据盈亏猜测。
- 无直接ID时，使用同账户scope、同标的/方向、有限执行时间窗口、可用持仓身份与数量，并要求窗口内唯一匹配成交。仅已确认的执行事件可用于此类关联；标注“执行记录关联”（corroborated），不冒充交易所直接来源标签。
- 分批平仓逐笔保存来源，允许混合来源。
- 无法证明来源时显示“已平仓（来源证据不足）”，不把未知强行归为“外部人工操作”。
- 归档订单、算法收据与策略关闭执行事件，避免最近一页历史滚动后证据消失；增强查询失败不降低已有更强归因，也不影响金额、费用、资金费计算。

有效算法历史仅使用只读GET，账户级5分钟缓存，共用监控读取限频与风控优先级；每次请求时间有界、失败不重试，不让历史查询的429污染风控待生效保护单端点冷却。

策略关闭journal只抽取必要订单ID，不保存完整CLI响应或凭据；journal失败不改变原平仓成功结果。确认关闭后请求账本刷新。

## 日志分层

- 巡检行：时间、持仓、本轮动作、决策计数、异常标的及连续无候选提醒。
- 动作摘要最多3项，优先保留异常及HTTP错误码，不在巡检行重复全部推理。
- 观察限制独立列出，不冒充交易动作。
- 本轮完整操作保存在decision_cycle.executed_actions；历史完整周期保存在账户隔离的execution_cycle事件中。
- 观察面板可展开“本轮完整执行记录”；管理员决策页可展开“近期完整执行记录”。完整WAIT证据仍在原审计卡片内。

示例（根据用户提供的10:45记录压缩，不是部署后产生的日志）：

```text
[2026-09-07 10:45:01] 巡检完成 | 持仓1/6(多1/空0) | 动作: 无开平仓 | 决策: 审查5 | 候选0 | WAIT4 | 不完整1(BTC) | 连续9轮无候选 | 观察:WLD
```

## 审计卡片布局

grid使用items-start，每个details使用self-start，不再随同排展开卡片拉高。已完成前轮复查的审计显示“前轮条件已复查”，不继续显示待复查。
