# 私有读取 HTTP 503 诊断与恢复

## 现场观察

持仓、余额的旧生产客户端曾出现 HTTP 503。排查时，在任何配置修改前，这两个接口已恢复200、code=0，
持仓守护和账本任务也恢复。容器未设置HTTP代理，旧浏览器UA与应用UA的同账户只读对照均成功。
因此不把凭据、UA、Nginx或服务器DNS当作已证实根因，也不把自然恢复归功于本补丁。
历史日志没有响应头/请求追踪ID，无法进一步区分当时是交易所上游服务还是前置网关故障。

## 补丁边界

- 不改账户、凭据、API主机、网络代理、模拟/实盘环境及策略门槛。
- 仅GET可在原调用总预算内最多尝试三次；429/500/502/503/504和确定的暂时性网络错误可重试。
- 保留Retry-After；等待超过剩余预算时直接报告不可用，不提前重试。
- 单次读取socket超时不超过共享预算的一半及剩余时间，防止首轮耗尽所有重试时间。
- urllib超时是socket级别，不是线程级硬终止；总预算后返回的响应不接受。
- 每次尝试重新签名、重新检查账户绑定；绝不从模拟切到实盘或换另一组凭据。
- POST等写操作始终只发一次，包括下单、平仓、撤单、改单、杠杆设置。
- 认证、参数和证书错误不重试。HTTP200但响应缺失code/data，不得解释为空仓。

## 可观测性

失败日志包含端点（不含查询参数）、类别、HTTP状态、尝试次数和允许格式的Cloudflare追踪ID。
不保存密钥、签名、口令、请求头或上游错误正文。
最终失败保存账户隔离的exchange_read_failure；重试后成功保存exchange_read_recovered。
诊断持久化失败不导致业务请求重发。持续故障仍按未知处理，绝不使用旧仓位或空数组授权交易。

## 验证

离线测试模拟503后恢复、连续失败、Retry-After、总预算、时间戳/签名变化、账户绑定变更、
实盘/模拟隔离、认证失败、证书失败、错误响应脱敏、写请求只发一次及持久化故障。
上线只执行余额/持仓的GET探测，并观察自然调度的position_guard、ledger_sync。
不会人为调用完整交易循环或平仓来测试网络修复。
