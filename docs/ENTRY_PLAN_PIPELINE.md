# 入场候选与完整执行路径修复

## 确认的问题

对连续无候选计数为 86 时的服务器取样：`c5012c1` 下 22 轮、110 条标的决策均是模型原始 WAIT，其中 85 条审计通过，25 条不完整（13 条缺前轮复查、12 条盈亏比拒绝缺价格方案）。

上一轮只去除了 `02_confidence_gatekeeper.py` 的 75/80 分限制，没有查到 `ai_factor_trader.execute_portfolio` 首次开多/开空仍要求 80 分、加仓仍要求 75 分。这是之前执行路径检查遗漏；它不是上述 110 个模型原始 WAIT 的直接原因，但会继续挡住随后出现的低评分候选。

## 新链路

1. 使用同一 signal frame 中有时间戳、已确认收盘的 15M/1H K 线，拒绝缺失、跨时点、不连续或未来数据，不增加新的采集请求。
2. 程序按固定定义识别两类待审查计划：收盘回收结构与收盘区间突破。它们是研究假设，不是已验证优势。
3. 目标固定采用此前 12 根已收盘 1H K 线的区间边界，止损采用最近三根已收盘 15M 的结构极值加 0.1 ATR 缓冲。不通过抬高目标来凑盈亏比；先按现有费用/滑点政策重算净 R:R。禁止追离触发位置超过 0.25 ATR 的不利报价；有利回撤仍须维持触发位置。
4. 将实际触发且几何/成本通过的草案放入模型输入。模型可选择 `candidate_id`，宿主核对本轮、标的、方向并补全原始价格与证据，减少重复抄写导致的输出缺陷。
5. 模型可以拒绝计划，但有草案仍 WAIT 时，须逐一提供实际字段支持的拒绝说明。绝不把审计不完整自动改成下单。
6. 移除完整首仓与加仓路径里的 LLM 评分大小门槛。已有止损、仓位数量、同向限制、浮盈/加仓次数、动量条件、最终账户风险与 OCO 保护仍然生效。
7. 程序计划价格取整后若结构失效，拒绝执行，不能自动扩大止损来修补；也禁止把程序计划整体平移到明显偏离的模拟盘报价。
8. 仍经原拦截插件与 `entry_gateway.prepare` 读取真实账户、挂单、杠杆、报价、风险预算。程序计划在此还须重新核对最终报价是否仍守住冻结触发位、是否追价过远、最终价格变动是否仅为 tick 取整；模型推理期间触发失效也拒绝执行。程序草案和模型选择都不是最终订单授权。

UI/日志分别显示程序草案、模型选择和最终候选/执行记录。不用草案数量清零“连续无授权开仓候选”计数。

## 验证

- 602 项后端测试、66 项前端测试；类型检查和构建通过。
- 新端到端测试覆盖实际 `execute_portfolio -> submit_protected_limit_order -> entry_gateway.prepare`，开多/开空的 0、47、79、80、100 分均到达最终风控。挂单、亏损加仓仍阻止入场；有效浮盈加仓低评分可到达最终风控。测试在最终风控处人为拒绝，绝无交易所写入。
- Windows headed Edge 检查前台监控和后台决策页，390/1440 宽度、亮/暗色共 8 组，无页面错误或横向溢出。API 为隔离模拟。
- 将官方允许读取的近期 K 线按每个历史快照时点截断，与归档 OHLC 逐项比对，450 条/90 轮均匹配；固定规则产生 43 个草案。仅 `c5012c1` 的 110 条/22 轮中有 3 个草案。
- 预先选择这 3 个机械触发的时点，各以旧/新输入调用同一个模型一次，共 6 次、每次最多 75 秒、不重试挑选。原有事实字段未改变，新增的是可追溯的历史 K 线引用与程序草案。
