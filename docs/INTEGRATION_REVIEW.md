## 本轮新增发现与修复

1. **多供应商模型混用**：模型表原先仅按模型名去重，激活、测试、删除未完整使用供应商 ID。改为供应商和模型的联合身份；前端同时传递供应商 ID，并修复“主脑生效”标识。
2. **旧地址 / 旧密钥残留**：扁平模型缓存会覆盖刚修改的供应商配置。供应商本地定义现在作为权威来源；无密钥模型不得借用其他供应商的环境密钥。
3. **错误的开关与删除语义**：默认供应商被加载函数强制重新启用；清空供应商可能移除当前模型。修复开关持久化，保护当前供应商及模型，冲突请求返回可处理的 400。
4. **激活失败却已切换**：密钥存储失败时仍可能先修改活动模型。改为先保存凭据，再保存活动选择；不再由激活操作把 LLM 主密钥额外写入明文 `.env`。
5. **Windows Worker 重复失败**：监督器不断启动依赖 POSIX 的 Worker 后失败。Windows 管理服务不再启动该 Worker，并在后台说明运行边界；未替换或绕过 `fcntl` 锁。
6. **有模拟盘余额但首页无法读取**：首页强制依赖 CLI。增加明确的账户只读 REST 资源白名单；有 API Key 时直接读取，OAuth-only 配置保留原 CLI 路径。一次采集使用同一份不可变环境/凭据快照，失败不切换 LIVE。
7. **查看页面会触发账本同步**：首页刷新会启动账本同步脚本，而该脚本可能改写账本并产生通知。移除监控刷新中的主动同步；交易/日报 Worker 中已有的同步入口保留。
8. **缓存与健康状态不一致**：前端只读旧 `is_stale` 字段，忽略后端 `data_health`。现在识别 STALE/PARTIAL/OFFLINE；读取失败时不能复用其他环境或其他账户的缓存。
9. **未设定本金却显示累计收益**：默认 10,000 被当作用户确认的本金。新增确认状态，未确认时不展示基于默认值的累计盈亏及 ROI；余额和真实账单仍可读取。
10. **把模拟盘或未运行任务写成实盘 / 正在运行**：改正固定“实盘持仓”、默认“扫描中”和“每 6 小时自动”等文案；移除未核实的“100% OCO 覆盖”及固定委员会 ACTIVE 标识。
11. **真实成功状态对比度不足**：实际模型测试成功后，“状态: 200”被 `opacity-75` 再次淡化。移除透明度并增加前端回归。
